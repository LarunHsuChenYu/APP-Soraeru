# 重要設計建議

## 1. 不要只問「你喜不喜歡」

「你覺得這個功能好不好？」通常只能得到偏主觀的答案。建議搭配具體情境，例如：

> 當您在餐廳看到不會念的外文菜名時，您會不會使用拍照辨識功能？

這樣取得的資料比較接近真實使用行為。

## 2. 將「正式發音」與「空耳」分開調查

問卷中應明確區分：

- 正式發音：作為正確學習依據
- 空耳：只作為記憶輔助

否則受訪者可能誤以為 APP 是用空耳取代正確發音。

## 3. 圖片功能必須確認真實需求

目前 MVP 的圖片流程是：

> 手機選圖或拍照 → 裝置端 OCR → 使用者確認單字 → AI 分析單字

因此問卷至少應確認：

- 受訪者會拍攝什麼內容
- 是否願意手動勾選單字
- 是否能接受 OCR 辨識錯誤
- 是否重視圖片不上傳雲端

## 4. 建議加入「排序題」

單純複選題容易讓所有功能都被選為重要。建議額外設計：

> 請從以下功能中選出您最想優先使用的前三項。

選項：

- 空耳產生
- 正式發音
- 圖片辨識
- 單字卡
- 複習提醒
- 例句
- 語音練習
- 雲端同步

這能協助團隊排定開發優先順序，避免需求無限制擴張。

## 5. 建議加入產品測試任務

如果受訪者能實際操作原型，應另外設計任務：

1. 輸入一個英文單字。
2. 使用圖片辨識找出一個單字。
3. 播放正式發音。
4. 選擇一個最容易記住的空耳。
5. 將單字儲存至單字卡。
6. 回到單字卡查看剛才的內容。

每個任務完成後再詢問：

- 是否容易找到功能？
- 哪一步最困難？
- 是否知道下一步要做什麼？
- 是否有不信任或疑惑的地方？

這類資料會比單純詢問偏好更適合用來改善 APP。
